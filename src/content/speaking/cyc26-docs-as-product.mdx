A talk from [Commit Your Code 26](https://www.commityourcode.com/). AI does not make documentation less important. It gives people another path through the same source material, which makes accuracy, ownership, and maintenance more consequential. The argument is simple: documentation should be managed with the same product discipline as the experience it supports.

When an agent reads your docs and acts on them, unclear or stale guidance stops being a confusing page and becomes a failed user task. So name the user and the job, give the system an owner while feature teams own the truth, and measure whether the task actually gets done — because a request is not a completed task.

## The numbers behind the talk

Two platform measurements anchor the "agents are reading your docs now" point. They come from different platforms, over different windows, classified by different rules, so they are two separate observations — not one trend line.

## Make docs work on the web first

Before adding agent-specific formats, make the documentation work well on the web. These are the established mechanisms the talk points to — each already has a defining specification.

Keep one maintained source of truth, then serve it in the forms that fit the job: readable pages for people, and machine-oriented representations for agents. These are access paths, not competing sources of truth.
